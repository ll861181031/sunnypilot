口径说明（为什么这些数字可信）

  • 配置 / 协商：配置是请求值，协商是驱动真正给出的值（cap.get()）。UVC 会静默回退到别的模式，两者不一致就说明请求没被满足。
  • 实测读取速率：采集线程每 1 秒滑动窗口内成功 read() 的帧数。这是硬件真实供帧速率，不是按请求值算出来的。
  • 预览不参与计数：MJPG 模式下驱动交出的帧本身就是 JPEG，预览直接原样转发，既不解码也不重编；编码（若需要）发生在 HTTP 线程而不是采集线程。
  • 单独 ↔ 同时：两台相机共用一条 USB 2.0 总线，同一设备在两路同时跑时的速率往往低于单独跑。对比表按「设备 + 模式」配对。
  • 占用：采集期间相机被本工具独占，行车栈（camerad）无法同时使用；反过来若 camerad 正在跑，这里会打不开并显示占用它的 PID。本工具不会去关闭任何别的进程。
